## 第一批：守卫失败的根因分析（候选，非批准）

36 个守卫失败（重算后为 47 个）大多不是 139 版改了逻辑，而是候选映射不全：
- 对 47 个失败方法做逐行比对后：30 个差异涉及仍未解析的类型；15 个目标成员没有绑定；2 个差异为资源 ID 变化或被调用方法改名（资源 ID 由工具自动映射）。
- 因此补齐映射比逐个写适配更正确；只有映射补齐后仍不一致的方法，才需要真正的人工适配。

本轮新增（`scripts/candidate_bindings/align_types.py`）：
- 位置对齐投票：同一条指令在旧版与新版只有类引用不同，则投一票。只有至少两个不同方法独立支持、且结论一致时才接受。
  （单个方法内的重复投票曾出现错误结论，已排除。）
- 循环"补类型 → 补成员"，至 426/601 类型、成员增加约 160 个。

当前结果：类型 426/601 有候选，175 个仍缺失；守卫失败 47 个（仍因缺失类型）；计划冲突 242。

已知问题：
- 绑定中的 `targetTreeSha256` 仍为旧值 `b4d1cf08…`，本环境重新解码得到的树哈希为 `560428af…`，两次全新解码结果一致，原因未知（环境重置后出现）。在用绑定进入 apply 前必须重新生成并核对。
- 1 个冲突 `Bindings unreviewed` 为设计使然，未设置 `reviewed: true`。
